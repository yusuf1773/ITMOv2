# План реализации: mate-in-one-ui

## Статус и основания
Требования и текущий дизайн утверждены пользователем 28 октября 2026 года. Этот план создан для проверки и НЕ УТВЕРЖДЁН. Все флажки означают будущую работу; в ходе составления плана код приложения и тестов не создаётся.

Основания: [требования](requirements.md), [утверждённый дизайн](design.md), [общий контракт](../../contracts/mate-in-one-api.md). Исторические формулировки статуса в prose требований/дизайна не отменяют явного утверждения пользователя, зафиксированного в spec.json.

## Правила выполнения и внешние предпосылки
- Каждая исполняемая задача рассчитана на 1–3 часа. Контейнерные группы не являются отдельными рабочими единицами.
- Пути и распределение файлов заданы в File Structure Plan дизайна. В текстах задач описаны возможности и результаты; границы привязаны к компонентам дизайна.
- Последовательность задаёт зависимости по умолчанию. Только 2.1 и 2.2 помечены (P): после задачи 1 они могут выполняться независимо. Общий файл проверок форматов и FEN принадлежит только 6.2, поэтому эти две задачи его не редактируют.
- Предусловие H для браузерной интеграции: backend предоставляет HTTP-раздачу страницы и ресурсов с одного origin Flask и JavaScript MIME; в разработке доступен браузерный стенд. Вне разработки тестовые файлы и метаданные проверок не публикуются. Это работа backend в его границе, а не скрытая задача UI на изменение Python.
- Предусловие B для 6.7: готов API по общему контракту и утверждён реальный набор пяти пригодных задач. Состав позиций предоставляет backend. До B применяются контрактные фикстуры без шахматного движка.
- Предусловие N для отрицательного прогона 6.7: backend-команда предоставляет изолированный тестовый экземпляр или управляемое тестовое состояние с работающим HTTP-сервисом и недоступным набором для проверки 503, затем доступный набор для проверки 404 с повреждённым телом. Подготовка и восстановление состояния принадлежат backend; остановка HTTP-сервиса не заменяет этот сценарий. Пока N не предоставлено, проверка и задача 6.7 не считаются завершёнными.
- Готовность H проверяется перед 6.1; при её отсутствии блокируется браузерная интеграция, а не объявляется выполненной. Она не требуется для разработки компонентов и их изолированных проверок.
- Нельзя изменять backend, общий контракт и before-agreement. Если отсутствует внешняя предпосылка, задача остаётся незавершённой; Python-конфигурация не добавляется в UI-границу.
- Обязательные проверки не помечены как необязательные. План не включает развёртывание, изменение требований или дополнительное проектирование.
