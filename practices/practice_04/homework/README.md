# Окружение олимпиадных C++ задач

Python 3.10+, g++ (C++17), системный libarchive для RAR. Python-зависимостей нет.
Решения пишет пользователь; тесты запускаются только по его явному запросу.

## Установка

Из этой папки:

```sh
git config --local core.hooksPath practices/practice_04/homework/git-hooks
```

Предыдущая локальная настройка: `practices/practice_03/git-hooks`; при установке этот каталог отсутствовал. Других действующих hooks в нём не было. Для возврата: `git config --local core.hooksPath practices/practice_03/git-hooks`.

Откройте homework как проект Codex и начните новый чат, чтобы загрузить локальную `.codex/config.toml` и skill `.agents/skills/cp-mentor/SKILL.md`. Локальная конфигурация применяется в доверенном проекте. MCP использует абсолютный путь: при переносе репозитория поправьте его. Настройка действует для чатов, открытых в homework, а не для соседних практик.

## Проверки

```sh
python3 scripts/style_check.py solutions/main.cpp
python3 scripts/style_check.py --staged
python3 scripts/verify_environment.py
```

Последняя команда проверяет только инфраструктуру на временных данных: PASS/FAIL checker, staged-содержимое hook, объявление MCP tools и блокировку STYLE_FAIL. Решения не компилируются и не запускаются. Пустой C/C++ файл получает FAIL за отсутствие newline. Пустые строки, в том числе из пробелов, запрещены внутри функций; вне функций разрешены. Любые определения макросов через `#define` запрещены. C++ файл с `main()` должен содержать вызовы `ios_base::sync_with_stdio(false);` и `cin.tie(nullptr);`; запись с `std::` тоже принимается. CRLF допустим; строковые литералы и комментарии не принимаются за директивы. Отступы проверяются в начале физических строк; директивы — после склейки строк с обратным слешем. Неизвестные расширения пропускаются.

Pre-commit проверяет staged C/C++ файлы всего репозитория, включая заголовки, новые и переименованные файлы; удалённые пропускает. Git index пользователя не изменяется. Проверяются согласованные правила стиля; это не компилятор и не полный C++ парсер.

MCP предоставляет `list_tasks`, `get_task`, `check_solution`. Исходный сервер взят из приложенного cp_tasks_mcp.rar; изменён вход `check_solution`: общий checker запускается на точных байтах source_code до чтения задачи/компиляции. Для Python C/C++ правила неприменимы. Перед вызовом тестирующего MCP агент также обязан выполнить checker снаружи и получить PASS. Наличие PASS не заменяет разрешения пользователя на тесты.

Skill перенесён из присланного текста, с сохранением подсказок, мотивации, доказательств и вывода сложности. Изменены конфликтующий bits/stdc++.h и разрешение писать код без явной просьбы. Добавлены согласованные ограничения тестирования. Он помогает учиться находить алгоритм самостоятельно, а MCP позволяет отдельно читать условия и, только по запросу, проверять решение.

README-upstream описывает исходный сервер, включая пример JSON для других клиентов; для Codex используется TOML в `.codex/config.toml`.
