# Brief: mate-in-one-backend

## Статус и источники

Обновлено 28 октября 2026 года по [утверждённому общему контракту](../../contracts/mate-in-one-api.md). Контракт утверждён пользователем с уточнениями, принятыми UI-командой. [Обновлённые требования](requirements.md) представлены пользователю для проверки и ещё не утверждены. Проектирование и создание исходников не начаты и этим обновлением не разрешаются.

Версия до согласования сохранена независимо: [исходный brief](before-agreement/brief.md) и [исходные требования](before-agreement/requirements.md). Существующие снимки не перезаписываются.

## Проблема

Пользователям тренажёра «Мат в один ход» нужны позиции и достоверная оценка попыток. UI разрабатывает другая команда; шахматные правила и проверка мата должны оставаться на backend.

## Текущее состояние

Есть документы спецификации и утверждённый общий контракт. Начальные требования актуализированы по результатам согласования команд. Реализация отсутствует; дизайн и задачи реализации не создаются. Основные steering-документы пока отсутствуют.

## Желаемый результат

Backend предоставляет пять пригодных задач и проверяет каждый ход относительно исходного FEN. Возвращает correct для допустимого мата, incorrect для допустимого хода без мата и illegal для недопустимого хода. Ошибки обращения и уточнение превращения отделены от шахматного результата. Попытки независимы.

## Подход

Заданные технологии: Python, Flask и python-chess, локальный JSON. Flask обслуживает предоставленный UI и API с одного origin; клиент использует относительный /api/v1. Контракт определяет внешний обмен и поведение интеграции. Внутреннее устройство будет определяться отдельно после проверки и утверждения требований.

Варианты из исходного brief больше не являются текущими альтернативами: принят формат from/to/promotion и выдача fen_after для допустимых ходов. Исходное обсуждение остаётся в before-agreement/brief.md.

## Объём

- **Включено:** пригодность пяти задач, упорядоченный каталог, полный FEN, проверка допустимости и мата, уточнение превращения, результаты и ошибки, независимость попыток, обслуживание предоставленного UI с API на одном origin.
- **Исключено:** БД, регистрация и авторизация, Stockfish, серверные пользовательские сессии, история и статистика, генерация задач, полноценная партия, выдача ходов для подсветки, серверный курсор и /next, разработка интерфейса.

## Кандидаты границ ответственности

- Данные: локальный набор из пяти задач, уникальные ID и пригодные исходные позиции.
- Шахматная проверка: допустимость, мат и необходимость уточнить превращение.
- Внешний обмен: операции и ответы по утверждённому контракту.
- UI-команда: доска, ввод, выбор фигуры, отображение, навигация и управление запросами.

Это одна спецификация backend. Кандидаты границ сохраняют смысл discovery и не являются утверждённой внутренней архитектурой или Boundary Commitments этапа проектирования.

## Вне ответственности

Backend не разрабатывает UI, не вычисляет пользовательский прогресс и не продолжает полноценную партию. Навигация и окончание каталога определяются интерфейсом. Размещение файлов UI через Flask не означает передачу его разработки backend-команде.

## Зависимости и потребители

- **Upstream:** набор пяти позиций, технологии из ограничений, [утверждённый контракт](../../contracts/mate-in-one-api.md), предоставленные UI-командой файлы интерфейса.
- **Downstream:** UI-команда и совместные интеграционные проверки.

## Существующие спецификации

- **Расширяемая:** mate-in-one-backend; используется существующий каталог.
- **Смежная:** mate-in-one-ui. Её документы этим обновлением не изменяются.

## Ограничения

Локальный JSON, Python + Flask + python-chess; без БД, регистрации, Stockfish и хранения пользовательских сессий. Единый origin, без отдельной настройки CORS. Язык документов — русский. Сейчас разрешено обновление документов спецификации; дизайн и исходники не создавать.

## Согласованный обмен и поведение

Полные схемы и ответы находятся в [контракте](../../contracts/mate-in-one-api.md); этот обзор не заменяет его.

| Операция | Маршрут | Данные |
| --- | --- | --- |
| Каталог | GET /api/v1/tasks | tasks: пять объектов id в стабильном порядке |
| Исходная позиция | GET /api/v1/tasks/{task_id} | id и полный fen |
| Попытка | POST /api/v1/tasks/{task_id}/attempts | Ровно from, to, promotion |

- Координаты a1–h8 в нижнем регистре; promotion: null или q/r/b/n. Клиентский FEN и UCI в теле не передаются.
- Результат: task_id, result, fen_after; для correct/incorrect FEN после хода, для illegal — null. Все три результата имеют статус 200.
- Шах без мата и пат — incorrect. Любой допустимый матующий ход — correct.
- При promotion: null сначала проверяется обычный ход: допустимый даёт correct/incorrect. Только если он недопустим, наличие допустимого превращения даёт PROMOTION_REQUIRED, а отсутствие обоих допустимых вариантов — illegal. При явной фигуре проверяется конкретный ход. UI выбирает фигуру из details.choices без автоматического ферзя.
- Ошибка: error с code, русским message и объектом details, без result/fen_after. Для PROMOTION_REQUIRED details содержит choices, в остальных случаях пуст.
- Приоритет: маршрут и метод → доступность набора → существование ID → Content-Type → JSON → структура и типы → формат хода → шахматная проверка. Полная таблица кодов и статусов — в разделе 8 контракта.
- UI показывает белые снизу, ID и текст задания; после correct применяет fen_after и блокирует попытки текущей задачи, после incorrect/illegal сохраняет исходную доску.
- UI использует каталог, допускает пропуски, меняет задачу после успешной загрузки. На последней задаче «Следующая задача» завершает просмотр без запроса несуществующего ID. Окончание не означает решения всех задач.
- Лимит ожидания UI — 10 секунд. Автоповторов нет; ручной повтор сохраняет запрос. При ошибке перехода повторяется тот же целевой ID. Устаревшие ответы игнорируются, в том числе для той же задачи.
- Исходные позиции не меняются, история на сервере не создаётся; ключ идемпотентности не требуется. Прекращение ожидания UI не гарантирует прекращения обработки сервером.

## Изменения после согласования

Относительно before-agreement/brief.md:

1. Статус несогласованного API заменён ссылкой на утверждённый контракт; требования оставлены на проверке пользователя.
2. Вместо вариантов тонкого API зафиксирована выдача fen_after для допустимых ходов.
3. Маршруты /puzzles заменены /tasks; UCI заменён from/to/promotion.
4. Добавлены точное условие PROMOTION_REQUIRED, details.choices и явный выбор фигуры.
5. Закреплены категории ошибок и приоритет с доступностью набора до проверки ID.
6. Зафиксированы порядок каталога, пропуски и окончание по явному действию UI на последней задаче; /next и серверный курсор не нужны.
7. Добавлены тайм-аут, ручные повторы, тот же целевой ID и игнорирование устаревших ответов.
8. Принято обслуживание UI и API Flask с одного origin и относительный /api/v1; отдельные CORS-правила исключены.
9. Закрыты вопросы подсветки, ориентации, заголовка, сообщений и позиции после попытки; обязанности UI и backend разделены явно.

10. Устранена неоднозначность превращения: обычный ход проверяется первым, затем возможность превращения. Уточнена смежная спецификация mate-in-one-ui. Форматы API сохранены.

## Оставшиеся вопросы

- Кто предоставит конкретные пять учебных позиций и какие это будут позиции.
- Численные цели производительности backend и доступности не заданы; десять секунд относятся к ожиданию UI.

Форматы, превращение, результаты, навигация, ошибки, тайм-аут, повторы и размещение уже согласованы контрактом и не числятся открытыми вопросами.
