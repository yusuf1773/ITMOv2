# Implementation Plan: Уроки и повторение «Татарча»

**Branch**: `hw8` | **Date**: 2026-11-21 | **Spec**: [spec.md](spec.md)

**Status**: согласован пользователем; реализация ведётся.

## Summary

Развить экспорт Figma Make в работающее приложение: проходить урок со словами и необязательной грамматикой, получать обратную связь, автоматически сохранять результат, открывать следующий урок и повторять изученное по простой очереди. Сохранить визуальные правила из [DESIGN.md](../../DESIGN.md). Использовать выбранную shadcn/ui для кнопок, полей, карточек и сообщений.

## Technical Context

- **Language/Version**: TypeScript, React 19, Vite 8, Tailwind CSS 4 (уже есть в экспорте).
- **Primary Dependencies**: shadcn/ui подключена; React и Tailwind установлены.
- **Storage**: `localStorage` через слой хранения с явными состояниями ожидания и ошибки. Один учащийся в текущем браузере; аккаунта и синхронизации нет. Согласовано.
- **Testing**: Vitest, React Testing Library и user-event для взаимодействий; в тестах подменять ответы слоя хранения (успех, пустые данные, задержка, ошибка). Минимум один сквозной тест клиентского сценария. Согласовано.
- **Target Platform**: современный браузер, включая экран шириной около 390 px.
- **Project Type**: одностраничное клиентское веб-приложение.
- **Constraints**: проверяемый учебный материал; доступность с клавиатуры; результат действия виден; повторная отправка и дубликаты прогресса исключены.
- **Scope**: один полный урок и путь повторения как минимальный работающий объём; новые уроки добавляются тем же форматом данных.

## Constitution Check

- Поведение, ошибки и критерии приёмки описаны в `spec.md`; открытые решения явно отмечены здесь.
- Основной сценарий заканчивается сохранённым результатом и открытым следующим уроком.
- Клавиатура, фокус, мобильный экран, ожидание, пустые данные и ошибки входят в проверки.
- Тесты проверяют видимое поведение, включая задержку и повторную отправку.
- Учебные примеры публикуются только после проверки источников.
- К реализации и следующему этапу переходим после согласования этого плана.

## Architecture and implementation sequence

1. **Подготовить основу интерфейса.** Подключить shadcn/ui по официальной [инструкции для Vite](https://github.com/shadcn-ui/ui/blob/main/apps/v4/content/docs/installation/vite.mdx). Использовать существующие alias `@/` и Tailwind 4. Вынести цвета, шрифт и отступы из `App.tsx` в тему; заменить типовые кнопки, поля и карточки компонентами shadcn/ui с вариантами из `DESIGN.md`. Сохранить экранный состав и образ маскота.
2. **Определить данные урока.** Описать типы урока, слова, правила, упражнения, ответа и результата. Каждое учебное утверждение хранить вместе с проверяемым источником. Для первого работающего урока выбрать и вручную проверить материал до включения в интерфейс. Заглушки Figma Make не считать учебным содержанием.
3. **Реализовать логику урока.** Последовательно показывать слова, необязательное правило и упражнения. Проверять пустой и слишком длинный ввод; после ответа блокировать его изменение и показывать верный вариант при ошибке. Завершать урок после всех ответов независимо от ошибок.
4. **Реализовать сохранение и прогресс.** Хранить завершённые уроки, результаты и записи повторения по устойчивым идентификаторам. Автоматическое сохранение выполняется один раз для результата, кратко повторяется при сбое и допускает ручную повторную попытку. Следующий урок открывается только после подтверждённого сохранения. Повторное прохождение не создаёт дубликаты.
5. **Реализовать повторение.** Сформировать очередь из изученных слов и правил: сначала наступивший срок, затем больше прошлых ошибок. Сессия содержит не более 10 заданий; ошибка возвращает задание один раз в конец. Сроки меняются по интервалам спецификации. При пустой очереди доступна свободная тренировка без дневного лимита; правильный ответ в ней не переносит плановый срок.
6. **Проверить сценарии.** Проверить урок целиком, сохранение, повторение, пустые данные, задержку, ошибку и повторную попытку, недопустимый ввод, двойное нажатие и клавиатуру. Сверить интерфейс с прототипом на широком и узком экране.
7. **Подготовить сдачу.** Добавить в README команды запуска и тестов, ссылку или экспорт прототипа, описание работы AI и внесённых исправлений, снимки ключевых состояний и фактический результат запуска проверок.

## Proposed project structure

```text
practice_08/
├── DESIGN.md
├── README.md
├── src/
│   ├── components/ui/       # компоненты shadcn/ui
│   ├── components/          # карточки уроков, маскот, обратная связь
│   ├── data/                # проверенный учебный материал и источники
│   ├── domain/              # типы, проверка ответов, очередь повторения
│   ├── storage/             # сохранение прогресса
│   ├── screens/             # курс, урок, результат, повторение
│   ├── App.tsx
│   └── index.css            # общая тема
├── tests/                   # проверки видимого поведения
└── specs/001-learn-and-review/
    ├── spec.md
    └── plan.md
```

Реализация небольшого курса пока оставляет экраны в `src/App.tsx`; данные, проверка ответов, расписание и сохранение вынесены отдельно. Папки `screens/` и дополнительное разбиение на компоненты остаются возможной доработкой при росте приложения. Сложную серверную архитектуру план не предусматривает.

## Согласованные решения и материал

Хранение прогресса и инструменты тестирования согласованы. Для первых трёх уроков использованы материалы портала «Электронное образование Республики Татарстан» и Татарской энциклопедии TATARICA; ссылки указаны в `src/data/lessons.ts` и README. Новые уроки требуют такой же проверки источников.
