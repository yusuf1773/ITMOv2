# Краткое описание: интерфейс «Мат в один ход»

## Проблема
Пользователю нужен простой способ просмотреть шахматную задачу, сделать один ход и узнать результат.

## Текущее состояние
Подготовлены требования UI и отдельная спецификация mate-in-one-backend. Пользователь утвердил [общий контракт API](../../contracts/mate-in-one-api.md) 28 октября 2026 года. Документы UI приведены в соответствие с ним; обновлённые требования ожидают проверки пользователя. Проектирование и реализация в рамках этой работы не выполнялись.

## Желаемый результат
Интерфейс получает каталог и первую позицию, показывает доску и сторону хода, принимает клетки и при необходимости серверного уточнения фигуру превращения. Он отображает результат Python-сервера, позволяет повторить попытку, пропустить задачу и завершить просмотр каталога. Ошибки обмена сопровождаются понятным сообщением; временные сбои допускают ручной повтор.

## Подход
Одна спецификация интерфейса на HTML, CSS и JavaScript. UI и API обслуживаются Flask с одного origin; клиент обращается к относительному /api/v1. UI отображает FEN, управляет выбором и состояниями ожидания, но не определяет допустимость хода, необходимость превращения или мат. Конкретное устройство интерфейса относится к будущему проектированию.

## Объём
- Включено: каталог, исходная позиция, доска с белыми снизу, ID и текст «Мат в один ход», выбор клеток и фигуры по details.choices, результаты correct/incorrect/illegal, независимые повторные попытки, следующая задача и пропуски, явное завершение просмотра, ошибки и ручные повторы.
- Исключено: регистрация, авторизация, база данных, сложный дизайн, шахматный движок в UI, подсветка допустимых ходов, готовые решения, полноценная партия, генерация задач, история, сохранение прогресса и серверные пользовательские сессии.

## Границы ответственности
- Представление: доска и сторона хода по FEN, координаты, ID, постоянный текст задания, выбор, сообщения и кнопки.
- Поведение UI: загрузка первой задачи и следующих ID по каталогу, промежуточный выбор превращения, ожидание, результат, повтор и завершение просмотра.
- Обмен: строго по утверждённому контракту; backend предоставляет позиции и всю шахматную оценку. Форматы и порядок ошибок не переопределяются UI.

## За границами спецификации
Реализация Python-сервера, выбор и проверка пригодности пяти учебных позиций, генерация задач, проверка правил и мата, поиск решения и хранение прогресса. Размещение на разных origins потребует отдельного согласования.

## Зависимости и потребители
- Зависимости: [контракт](../../contracts/mate-in-one-api.md) и [требования backend](../mate-in-one-backend/requirements.md). Backend выдаёт пять уникальных ID в стабильном порядке, полный FEN и независимый результат каждой попытки.
- Потребители: будущая реализация frontend и совместная проверка интеграции.

## Связанные спецификации
Смежная спецификация — mate-in-one-backend. Этот документ не меняет её требования, контракт или статусы утверждения.

## Ограничения
HTML, CSS и JavaScript. Без регистрации, базы данных и сложного дизайна. Шахматная логика в UI запрещена. Полный ответ ожидается не более 10 секунд; это клиентский предел ожидания, а не гарантия производительности сервера.

## Согласованные решения вместо прежних допущений
- После incorrect и illegal остаётся исходная позиция, выбор сбрасывается, повторная попытка доступна. После correct применяется серверный fen_after и новые попытки блокируются.
- Пропуски разрешены. Следующий ID выбирается по каталогу без числа 5 в логике навигации; ошибка загрузки не продвигает прохождение.
- Последняя задача остаётся решаемой. Только нажатие «Следующая задача» на ней завершает просмотр с сообщением «Задачи закончились»; это не означает решения всех задач.
- PROMOTION_REQUIRED обрабатывается выбором из details.choices, а не обычной ошибкой с кнопкой «Повторить». Новая попытка содержит явно выбранную фигуру.
- Порядок ошибок: маршрут/метод → доступность набора → ID → Content-Type → JSON → структура/типы → формат → шахматная проверка. Недоступный набор даёт 503; неизвестный ID при доступном наборе — 404 до разбора тела.
- Сетевые сбои, тайм-аут и 5xx допускают ручной повтор того же запроса. Автоматических повторов нет; устаревшие ответы не меняют экран, включая новые попытки той же задачи.
- Белые снизу; ID и сторона хода отображаются без отдельных title и поля стороны хода. Один origin Flask, относительный /api/v1, отдельный CORS не требуется.

## Изменения после согласования 28 октября 2026 года
1. Несогласованные форматы заменены ссылкой на утверждённый контракт и его решениями: каталог, FEN, from/to/promotion, результаты и ошибки.
2. Добавлены серверное уточнение превращения, явное завершение последней задачи, порядок ошибок, тайм-аут и повторы.
3. Обновлены границы UI/backend и размещение с одного origin. Исправлено прежнее утверждение об отсутствии смежной спецификации.
4. Исходные brief.md и requirements.md сохранены независимыми копиями в before-agreement; существующие копии не перезаписываются.

## Статус
Контракт утверждён, обновлённые требования UI представлены для проверки и ещё не утверждены. Проектирование, задачи реализации и исходники приложения не создавались и не изменялись в рамках этого обновления.
