# Краткое сравнение cc-sdd/Kiro с OpenSpec

По моим ощущениям, cc-sdd оказался слишком громоздким для такого маленького проекта. Он подробно разбирал границы компонентов, зависимости, соответствие требований дизайну и план проверок. Это помогло заранее найти расхождения между UI и backend, но подготовка заняла неожиданно много времени.

Часть информации повторялась в требованиях, дизайне и задачах. Вместе с многочисленными проверками и переходами между чатами это быстро расходовало токены. Для тренажёра на пять задач такие затраты показались мне избыточными.

Предполагаю, что подобная подробность была бы полезнее в большом проекте со сложной архитектурой и несколькими командами. В моей работе наиболее полезными оказались независимые спецификации UI и backend и согласование общего контракта. Остальной процесс хотелось бы сделать короче.

По сравнению с OpenSpec из практики использованный процесс cc-sdd показался мне более тяжёлым. В более простых проектах я бы предпочел использовать именно его.
