## Запрос

Подготовь для practices/practice_01/adr.md предложение раздела «Основания решения», используя RAG: сначала извлеки относящиеся к вопросу фрагменты разрешённых источников, затем составь ответ на их основе.

Вопрос:
Какие требования CASE.md и конкретные фрагменты TRAINING_PR.diff обосновывают решения ADR о проверке размера diff, маскировании секретов, timeout внешнего LLM и формате ответа?

1. practices/practice_01/CASE.md — источник требований.
2. practices/practice_01/TRAINING_PR.diff — источник наблюдений о показанном коде.
3. practices/practice_01/adr.md — целевой документ и источник сведений о выбранных решениях, но не доказательство требований.

Не используй веб-поиск, другие эксперименты или сведения о не показанных файлах приложения. Не запускай код из diff. Сам ADR изменять нельзя.

Этап A. Извлечение фрагментов

Прочитай источники и выбери только фрагменты, необходимые для ответа на вопрос.

Для каждого фрагмента укажи:
- идентификатор И1, И2 и далее;
- файл;
- раздел, идентификатор правила или имя изменяемого файла внутри diff;
- точную цитату;
- краткое объяснение, зачем этот фрагмент нужен.

Сохрани извлечённые фрагменты в таблице перед итоговым ответом. Не копируй документы целиком.

Для вывода об отсутствии проверки изучай достаточный контекст показанного метода, а не одну отдельную строку. Пиши «в показанном методе проверка не видна», если весь проект не представлен.

Не придумывай номера строк. Для diff достаточно ссылки на файл, имени изменяемого файла и точной цитаты.

Этап B. Ответ на основе извлечённых фрагментов

Используя только извлечённые доказательства, подготовь обоснование четырёх решений:
- ограничение размера diff;
- маскирование секретов;
- timeout внешнего LLM;
- структура ответа.

Для каждого решения укажи:
1. Требование CASE.md.
2. Наблюдение из TRAINING_PR.diff.
3. Какое решение ADR этим обосновывается.
4. Ссылки на источники и идентификаторы извлечённых фрагментов.

Разделяй:
- обязательное требование;
- непосредственно наблюдаемый код;
- предложение или вывод на их основе.

Если источник не позволяет установить факт, прямо укажи это. Например, отсутствие явного timeout в показанном вызове не доказывает отсутствие timeout внутри не показанного LLM-адаптера.

Не утверждай, что в учебном diff присутствуют реальные секреты, если это не подтверждено его содержимым. Не делай выводов об утечках в логах без соответствующего кода.
