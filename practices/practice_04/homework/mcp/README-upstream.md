# MCP для задач по программированию

Сервер принимает путь к ZIP/RAR в каждом запросе, читает именно этот архив и предоставляет три инструмента:

- `list_tasks(archive_path)` — список задач, число тестов и наличие разбаловки.
- `get_task(archive_path, task_id)` — условие, ограничения и примеры.
- `check_solution(archive_path, task_id, source_code, language, ...)` — компиляция и запуск решения на тестах.

Проверка возвращает общий вердикт, число пройденных тестов, упавшие группы и причину первой ошибки. Если архив задаёт баллы за группы или отдельные тесты, отчёт включает заработанные и максимальные баллы; если разбаловки нет, баллы не выводятся. `show_failed_tests: true` добавляет входы и ожидаемый/фактический вывод для упавших тестов.

## Что нужно для запуска

- Python 3.10+.
- `g++` для C++17 и системная библиотека `libarchive` для RAR. Python-библиотеки не требуются.
- Для Python-решений используется тот же Python, которым запущен сервер.

Архив передаётся инструменту как `archive_path`. Путь должен существовать и быть доступен процессу MCP-сервера. Поэтому если прикреплённый файл виден модели под локальным путём, передай этот путь в вызов. Сервер не отправляет весь архив в текст запроса модели и не сохраняет фиксированный список архивов.

Если нужна постоянная коллекция, можно задать необязательный `CP_TASK_ARCHIVES`; пути разделяются двоеточием на Linux/macOS и точкой с запятой в Windows. Тогда `list_tasks` можно вызвать без аргумента `archive_path`.

Пример запуска в терминале:

```sh
python3 /absolute/path/outputs/cp_tasks_mcp.py
```

## Подключение в Codex

Добавь сервер в конфигурацию MCP-клиента, подставив абсолютный путь к файлу и свои архивы:

```json
{
  "mcpServers": {
    "cp-tasks": {
      "command": "python3",
      "args": ["/absolute/path/outputs/cp_tasks_mcp.py"],
      "env": {}
    }
  }
}
```

Вызови `list_tasks` с путём к переданному архиву. Затем используй тот же `archive_path` и выданный `task_id` для `get_task` или `check_solution`. Чтобы получить входы провалившихся тестов, укажи `show_failed_tests: true`.

## Границы проверки

Если checker задачи компилируется, сервер использует его. Если checker отсутствует или не собирается, сервер сравнивает токены ответа с эталонным файлом и добавляет предупреждение в результат. Такое сравнение подходит для обычного единственного ответа, но не заменяет checker для задач с несколькими корректными ответами.

У программы решения есть ограничения времени, памяти, размера файла и вывода. Эти ограничения не являются полной изоляцией: исполнять следует только собственный доверенный код. Исходные архивы сервер не меняет.
