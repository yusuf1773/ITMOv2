# Практика 3 — локальный помощник на Qwen3 8B

Дата: 7 октября 2026 года. Файлы и проверку подготовил Codex по просьбе пользователя. OpenCode использован как клиент тестируемой локальной модели. Это отступление от формулировки README о подготовке всех файлов агентом Build сделано по явному указанию пользователя.

## Устройство и модель

- CPU: AMD Ryzen 7 H 255 with Radeon 780M Graphics, 8 ядер / 16 потоков.
- Оперативная память: около 22 GiB, swap 8 GiB. На этапе подготовки доступно около 15 GiB.
- ОС: `Linux-7.0.0-34-generic-x86_64-with-glibc2.43`; Python 3.14.4. Полные сведения: `lab/results/20261007-232607/environment.json`.
- Ollama 0.34.4; OpenCode 1.18.35.
- Установленная модель: `qwen3:8b`, ID `500a1f067a9f`, 8.2B параметров, Q4_K_M, размер весов около 5.2 GB.
- Создан отдельный профиль `itmo-practice03-qwen8b`, ID `8270c0750e61`. Существующие профили пользователя `itmo-agent` и `itmo-local` не заменялись.
- `ollama ps` подтвердил контекст 16 384, размещение 100% CPU, загруженный размер около 7.9 GB. Это наблюдение, а не измерение пикового потребления памяти.
- Сервер: `http://localhost:11434/v1`. В конфигурации разрешён только провайдер `ollama`; автоматическая публикация выключена; запуск использует `--pure`.

Выбрана уже установленная пользователем Qwen3 8B: скачивание другой модели не требуется. В лекции показан профиль 64k для Qwen3.5; у установленной Qwen3 `ollama show` сообщает предел 40 960. Поэтому параметры шаблона не перенесены вслепую: для маленького сервиса выбран контекст 16k, согласованный между Modelfile.agent и OpenCode. Входы и инструменты занимают существенно меньше этого лимита. Увеличение контекста само по себе не исправляет неверный выбор файлов.

## Конфигурация и изоляция

`lab/Modelfile`: Qwen3 8B, 4096 токенов для прямого чата, temperature 0.2 и инструкция не выдумывать факты. `lab/Modelfile.agent`: та же модель, 16384 токена и temperature 0.2, без дополнительного SYSTEM. Для OpenCode инструкция задаётся в `lab/demo/repo-system.txt`; заявленный предел ответа в конфигурации — 2048 токенов, максимум 8 шагов.

Тестируемый `local-guide` может использовать только read, glob и grep. Другие действия и доступ вне рабочей папки запрещены конфигурацией. Для каждого вопроса создаётся новая сессия. Сценарий копирует только шесть файлов demo во временную папку и явно задаёт `--dir`, `PWD`, конфигурацию и абсолютные пути. Это ограничение средствами клиента, не отдельный контейнер.

Эталоны подготовлены по исходникам до тестовых запусков. В тестовую папку не копируются отчёт, эталоны и прошлые ответы. Полные входы и их SHA-256 сохранены рядом с результатами итоговой серии. Содержимое учебного сервиса не изменялось.

К каждому вопросу добавляется одинаковая инструкция: прочитать README.md, Makefile, service.py и test_service.py инструментом read, затем ответить по этим источникам с указанием файла и строки. `/no_think` добавлен в запрос как инструкция Qwen; отдельная API-настройка `think=false` в OpenCode не проверялась, поэтому гарантированное отключение внутреннего reasoning не заявляется.

## Воспроизведение

Из `practices/practice_03/lab`:

```bash
ollama create itmo-practice03-qwen8b -f Modelfile.agent
python3 run_questions.py
make test
```

Каждый повтор создаёт новый каталог `lab/results/<дата-время>/`, сохраняет JSONL-события, stderr и время процесса. Таймаут одного вопроса — 600 секунд. Для интерактивного демо:

```bash
cd demo
opencode --pure --agent local-guide --model ollama/itmo-practice03-qwen8b
```

Пример запроса для демонстрации: «Прочитай service.py инструментом read. Что произойдёт, если дважды подписать Ann? Укажи строки».

Вопросы различаются, поэтому эти пять времён не являются повторными измерениями одного задания. Три прогретых повтора не выполнялись; холодная загрузка отдельно в этой серии не измерялась.

**Вывод:** содержательные ответы на все пять вопросов совпали с эталонами. Но полное соблюдение инструкции не достигнуто: модель иногда пропускает файлы и может указать недостоверную строку. Результаты описывают только эту серию и не являются сравнением нескольких моделей или настроек.

Конфигурация подходит для небольшого учебного репозитория на CPU. Ожидание 1–3 минуты на вопрос и неполные доказательства ограничивают удобство. Увеличение окна контекста не заменяет точный путь, явную инструкцию read и проверку ответа.
